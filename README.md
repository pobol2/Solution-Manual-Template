# Solution Manual Template

A LaTeX framework for writing a solution manual for any textbook or subject:
problem, solution, answer and verification sections, standalone TikZ/PGFPlots
figures, and one `latexmk` build that compiles the manual and its figures
incrementally.

```
solution-manual/        Shared framework (classes, build rules): never edited by a project
latexmkrc               Project build file: loads solution-manual/latexmkrc
.vscode/settings.json   LaTeX Workshop settings
main.tex                Class options, titles, author, appearance, chapters
COMPLETION.md           Completion report, generated by the build (when enabled)
mypackages.sty          Packages of the manual
mycommands.sty          Commands of the manual
mytheme.sty             Theme color, shared by the manual and the figures
myfigures.sty           Packages, colors and TikZ/PGFPlots styles of the figures
Chapters/, Figures/     Example content: replace it with your own
```

## Setup

Install a TeX distribution (MiKTeX or TeX Live) with pdfLaTeX, LuaLaTeX and
`latexmk`, and Perl (on Windows, e.g. Strawberry Perl). Install any missing
packages through the distribution's package manager, or allow MiKTeX to install
them when prompted. For VS Code, install the LaTeX Workshop extension.

To start a manual, set the titles and author in `main.tex`, then replace the
example chapters and figures.

## Compiling

From the project root, run

```sh
latexmk
```

or, in VS Code, **LaTeX Workshop: Build LaTeX project** (or save a file). Both
run the same command with the same options, from `latexmkrc`:

- pdfLaTeX compiles the manual, with SyncTeX, as many times as needed;
- LuaLaTeX compiles each figure used by the manual when its PDF is missing or
  out of date. A figure is rebuilt when its source, or a file of the project or
  framework that it reads (`SolutionFigure.cls`, `mytheme.sty`, `myfigures.sty`,
  an `\input` data file or CSV), changes; unchanged figures are reused;
- the finished PDF is copied to the project root, with the completion report
  `COMPLETION.md` when [completion tracking](#completion-tracking) is on (the
  report can also be [inserted into a README](#report-in-a-readme)).

| Location             | Contents                                                    |
| -------------------- | ----------------------------------------------------------- |
| `main.pdf`           | The finished manual                                         |
| `COMPLETION.md`      | Completion report (only with completion tracking)           |
| `Figures/<name>.pdf` | Generated figures                                           |
| `build/`             | Everything else: `main.log`, `main.synctex.gz`, `main.pdf`, ... |
| `build/figures-aux/` | Compilation files of the figures (look here when a figure fails) |

`build/` and `Figures/*.pdf` are ignored by Git. The root `main.pdf` and
`COMPLETION.md` are kept in the repository as previews of the examples;
rebuilding refreshes them.

For a clean build, remove `build/` and only the generated figure PDFs that have
a matching `.tex` source, then run `latexmk` again. Keep any imported PDF
illustrations that have no matching source file.

In VS Code, the viewer shows `build/main.pdf`, next to its SyncTeX file:
forward search and Ctrl+click inverse search work as usual. Each figure starts
with `% !TEX root = ../main.tex`, so that saving a figure builds the manual
(and therefore the figure); keep this line in new figures. If you change
`$out_dir` in `latexmkrc`, change `outDir` and `auxDir` in
`.vscode/settings.json` to match.

## Writing problems

```tex
\begin{problem}
{Question.}
{Worked solution.}
{Final answer.}
[Verification.]
\end{problem}
```

The solution and the answer are optional: leave either argument empty (`{}`)
to omit it. An argument with only spaces or blank lines counts as empty. For a
problem in parts, give the main question with `{}{}`, then add `subproblem`
environments, which take the same arguments:

```tex
\begin{problem}{Main question.}{}{}\end{problem}
\begin{subproblem}{Part (a).}{Solution.}{Answer.}[Check.]\end{subproblem}
\begin{subproblem}{Part (b), a proof.}{Proof.}{}\end{subproblem}
```

Verification is optional and comes last, after the answer: omit
`[Verification.]` entirely when it is not needed. Empty or whitespace-only
contents inside `[...]` also omit it. It appears under a small-caps
"Verification:" heading, matching the solution heading, and can span pages.
Place the opening `[` on the same line as the answer's closing `}` or on the
next line, with no intervening blank line. Balanced nested brackets work;
protect unmatched square brackets, such as a half-open interval, by wrapping
the verification contents in braces:

```tex
{Answer.}
[{Check that $x \in [0,1)$.}]
```

The `problem label`, `solution label`, `answer label` and `verification label`
keys of `\SolutionManualSetup` customize the headings. Verification does not
change completion status; that still depends on the solution or the explicit
`[done]` / `[not done]` status before the question.

Problems start on a new page (see `problem on new page`); questions can
span several pages, and an answer box is kept on the page where its solution
ends. Final-answer boxes stay whole, so their contents must fit on one page.
Long solutions can paginate between text and displayed equations. Arguments can
contain displayed equations (`align`, ...),
figures and tables, but not verbatim text.

`Chapters/` shows every case: ordinary problems, subproblems with and without
solution or answer, verification sections, a question alone, equations, figures,
a table, references across chapters, and (`3-Sections.tex`) sections with their
own numbering, a textbook section number, `\probref` and completion tracking.
`4-Showcase.tex` combines most of them on one page.

## Chapters, sections and numbering

Problems are grouped by the standard `\chapter`, `\section` and `\subsection`:
a problem belongs to the last of these headings before it. All the problems of
a chapter are at the same level: directly in the chapter, all in its sections,
or all in its subsections (LaTeX stops with an error otherwise). Chapters can
have different structures, and any problem can have parts:

```tex
\chapter{Kinematics}                 % problems directly in the chapter
\begin{problem}...\end{problem}

\chapter{Dynamics}                   % problems in sections
\section{Newton's laws}
\begin{problem}...\end{problem}
\section{Friction}
\begin{problem}...\end{problem}
```

Starred headings (`\section*`) are plain titles: they group nothing.

### Numbering

The `problem numbering` key sets where the numbering restarts at 1:

| Value               | Restarts at                   | `\ref` of problem 2 of section 3.1 |
| ------------------- | ----------------------------- | ---------------------------------- |
| `chapter` (default) | each chapter                  | `3.n` (its number in chapter 3)    |
| `subdivision`       | each section (or subsection)  | `3.1.2`                            |
| `continuous`        | never                         | `n` (its number in the manual)     |

With `subdivision`, the problems of a chapter without sections are numbered
within the chapter. Set the key in the preamble, or in the document before a
`\chapter` to change the numbering from that chapter on (a change restarts
the numbering at 1):

```tex
\SolutionManualSetup{problem numbering=subdivision}
\chapter{...}
```

### Textbook numbers

To show the textbook's number instead of the manual's, put `\textbooknumber`
before a `\chapter`, `\section` or `\subsection`:

```tex
\textbooknumber{\S 12}
\section{Series}            % §12; its subsections are §12.1, §12.2, ...
```

The number appears in the heading, contents, bookmarks, running header and
references. The automatic numbering of the next headings is unchanged.

### Page breaks, contents, bookmarks and headers

With `problem on new page` (the default), a section or subsection heading
starts a new page and its first problem follows it on that page; consecutive
headings, and any text between a heading and its first problem, share that
page. Chapter titles keep their own page. Without `problem on new page`, a
heading moves to the next page when less than six lines remain.

Problems are listed under their heading in the contents, bookmarks are nested
(section bookmarks show their number), and the right-hand header shows the
section where numbering restarts, e.g. `§12  Problem 2.`. Hyperlink targets
stay unique when problem numbers repeat.

### References

- `\label` in a question, then `\ref`: the full number, `1.2`, `1.2(a)`,
  `3.1.2`, `§12.2(a)`;
- `\probref{unit}{number}`: a link to a problem from the number of the
  chapter or section where its numbering restarts, as shown (the chapter in
  chapter and continuous numbering), and its own number:

  | Reference              | Text                  |
  | ---------------------- | --------------------- |
  | `\probref{1}{2}`       | Chap. 1 Prob. 2       |
  | `\probref{3.1}{2}`     | Sec. 3.1 Prob. 2      |
  | `\probref{\S 12}{2}`   | §12 Prob. 2           |
  | `\probref{4}{47}`      | Prob. 47 (continuous) |
  | `\probref[text]{1}{2}` | text                  |

  Write a textbook number as in `\textbooknumber`. Like `\ref`, an unknown
  problem gives "??" and a warning;
- equations and figures: the usual `\label`, `\eqref` and `\ref`.

The keys `chapter abbreviation`, `section abbreviation` and
`problem abbreviation` change "Chap.", "Sec." and "Prob.". If two subdivisions
are shown with the same number, `\probref` links to the first one and LaTeX
warns.

## Completion tracking

Turn it on in the preamble:

```tex
\SolutionManualSetup{completion tracking=true}
```

A problem or part is **done** when its solution is not empty. Otherwise it is
**not done**, even if it has an answer. Unfinished problems and parts show a
small "Not done" in their title and in the contents; finished ones show
nothing. Without completion tracking, no marker, overview or report appears,
and `[done]` and `[not done]` have no effect.

An optional argument overrides the automatic status:

```tex
\begin{problem}[not done]{Question.}{Partial solution.}{}\end{problem}
\begin{subproblem}[done]{Question.}{}{Answer only, on purpose.}\end{subproblem}
```

A problem with parts is done when all its parts are done: its own solution,
usually empty, does not matter, but `[not done]` on it keeps it unfinished.
Each problem counts once, parts or not, in its own chapter and subdivisions.
Headings without problems are not counted.

`\completionoverview` adds a linked overview with done/total counts for the
manual, each chapter and each subdivision that has problems, and the
unfinished problems under each heading, e.g. "Not done: Problem 2 (b, c)".
Place it after `\tableofcontents`, or at the end of the manual, where it is
complete after a single compilation.

### Markdown report

The build also writes `COMPLETION.md` in the project root, from the same data:
a summary line and a table to link from a repository README, or to
[insert into it](#report-in-a-readme) (see the example's
[`COMPLETION.md`](COMPLETION.md)). There is no list or count to maintain: run
`latexmk` to refresh the PDF and the report.

The report reflects the latest compilation. The contents markers, the markers
of problems with parts and an overview at the start of the manual use the
previous one, so they need a second pass, which `latexmk` runs automatically;
with plain `pdflatex`, run it twice (LaTeX warns "Completion data may have
changed" when needed). The report is written to `build/main-completion.md` and
copied to the root when it has changed. To keep it in `build/` only, add
`$completion_report = '';` to the project's `latexmkrc`; give another file name
to rename it. Turning completion tracking off leaves the last `COMPLETION.md`
in place: delete it if it is no longer wanted.

### Report in a README

The build can also put the report inside a Markdown file, such as the
project's `README.md`. Add these two lines where the report goes:

```markdown
<!-- completion report: begin -->
<!-- completion report: end -->
```

and name the file in the project's `latexmkrc`:

```perl
$completion_readme = 'README.md';  # the report goes between the markers
$completion_report = '';           # optional: no separate COMPLETION.md
```

After each successful build, the text between the markers is replaced with the
report; the markers stay. Each marker must be alone on its line; markers in
fenced code blocks, like the ones above, are ignored. The file keeps its line
endings and is rewritten only when the report has changed. If a marker is
missing, `latexmk` warns and leaves the file unchanged; the build still
succeeds. `$completion_report` works as before, so without
`$completion_report = ''` the build writes both.

## Customization

Customize the manual from the project files only.

**Class options** in `main.tex` (`12pt`, `twoside`, ...) are passed to the
`report` class.

**`\SolutionManualSetup{...}`**, in the preamble of `main.tex`:

| Key                    | Default                                  |
| ---------------------- | ---------------------------------------- |
| `author`               | empty                                    |
| `title`                | empty                                    |
| `subtitle`             | empty (the line is then omitted)         |
| `title prefix`         | `Solutions to`                           |
| `date`                 | `\today`                                 |
| `author label`         | `Author`                                 |
| `contents label`       | `Table of Contents`                      |
| `problem label`        | `Problem`                                |
| `solution label`       | `Solution:`                              |
| `answer label`         | `Answer to Problem`                      |
| `verification label`   | `Verification:`                          |
| `footer`               | title prefix, title and `by` author      |
| `theme color`          | `ThemeColor` of `mytheme.sty` (titles, links, answers; manual only) |
| `question background`  | `gray!5!white`                           |
| `question frame`       | `gray!50!black`                          |
| `subquestion frame`    | `gray!75!black`                          |
| `answer background`    | `ThemeColor!5!white`                     |
| `answer frame`         | `ThemeColor`                             |
| `subanswer frame`      | `ThemeColor`                             |
| `layout`               | `a4paper, margin=25mm` (any `geometry` options) |
| `problem on new page`  | `true`                                   |
| `problem numbering`    | `chapter` (or `subdivision`, `continuous`) |
| `chapter abbreviation` | `Chap.` (`\probref`)                     |
| `section abbreviation` | `Sec.` (`\probref`)                      |
| `problem abbreviation` | `Prob.` (`\probref`)                     |
| `completion tracking`  | `false`                                  |
| `not done label`       | `Not done`                               |
| `done label`           | `Done` (report column)                   |
| `completion title`     | `Completion` (overview and report)       |
| `completion total label` | `All problems`                         |

Colors accept any `xcolor` expression. Other texts come from standard LaTeX
commands: `\chaptername`.

**Title and author in other settings**: `\authorName`, `\mainTitle` and
`\firstTitle` (the subtitle) hold the values of `author`, `title` and
`subtitle`. Use them wherever a setting needs the title or author, for example
`footer={Solution to \mainTitle~by \authorName}`. Setting them with
`\def\authorName{...}`, `\def\mainTitle{...}` and `\def\firstTitle{...}` still
works.

**Theme color**: set it once in the optional `mytheme.sty`, which both classes
load, so the manual and the figures stay matched:

```tex
\colorlet{ThemeColor}{blue!50!black}
```

Changing it rebuilds the manual and every figure. Without the file, the theme
color is `red!50!black`. The `theme color` key above changes the manual only.

**Packages and commands** go in `mypackages.sty` and `mycommands.sty`, which
`main.tex` loads.

**Build settings** go at the end of the project's `latexmkrc`:

| Variable             | Default                                                   |
| -------------------- | --------------------------------------------------------- |
| `$completion_report` | `'COMPLETION.md'` (copy of the report; `''` for none)      |
| `$completion_readme` | `''` (Markdown file to [insert the report into](#report-in-a-readme), e.g. `'README.md'`) |

## Figures

Create each figure as `Figures/<name>.tex`, using the same class font size as
`main.tex` (currently `12pt`):

```tex
% !TEX root = ../main.tex
\documentclass[12pt]{SolutionFigure}
\begin{document}
\begin{tikzpicture}
    \draw[axis] (0, 0) -- (3, 0) node[axis label, right] {$x$};
    \draw[curve, domain=0:2.5] plot (\x, {0.4*\x*\x});
\end{tikzpicture}
\end{document}
```

Include its PDF at natural size to preserve text and stroke sizes. Keep the
`Figures/` prefix so the [build rules](#compiling) can find its source:

```tex
\begin{figure}[H]
    \centering
    \includegraphics{Figures/name.pdf}
    \caption{...}\label{fig:name}
\end{figure}
```

The manual includes these commented examples:

| Source | Demonstrates |
| ------ | ------------ |
| [RightTriangle.tex](Figures/RightTriangle.tex) | Geometry, angles and dimensions |
| [Tangent.tex](Figures/Tangent.tex) | TikZ axes, grid, curve, shaded region and tangent |
| [Euclid.tex](Figures/Euclid.tex) | Flowchart and shared node spacing |
| [Quadratic.tex](Figures/Quadratic.tex) | Default plot, centered axes and point markers in a verification |
| [Plots.tex](Figures/Plots.tex) | Automatic curve styles, legends, subplots, CSV data and local overrides |

### Shared appearance

`SolutionFigure` loads TikZ (libraries `arrows.meta`, `calc`, `angles`, `quotes`,
`positioning`, `shapes.geometric`) and PGFPlots (`compat=1.18`, `groupplots`).
It crops figures with a 2 pt border and provides these TikZ styles:

| Styles | Use |
| ------ | --- |
| `diagram node`, `decision node`, `diagram arrow` | Flowcharts; default node spacing 7 mm vertically, 12 mm horizontally |
| `axis`, `axis label`, `tick`, `grid lines`, `guide` | Axes, grids and construction lines |
| `curve`, `highlight`, `region` | Curves, emphasized lines and shading |
| `point`, `plot points`, `vector` | TikZ points, plot markers and arrows |
| `angle arc`, `right angle mark`, `dimension` | Angles and lengths |
| `annotation` | Small gray text |

The shared colors are `FigureAccent` (`ThemeColor`, from
[`mytheme.sty`](#customization)), `FigureGuide` (`black!50`) and `FigureFill`
(`FigureAccent!12`). Set project colors, packages, TikZ styles and PGFPlots
settings in **`myfigures.sty`**, loaded by every figure after `mytheme.sty`; a
`\colorlet{FigureAccent}{...}` there gives the figures a different accent. The
figures do not read `main.tex` or inherit its font settings automatically.

### Plots

Inside `tikzpicture`, use the usual PGFPlots `axis` environment:

```tex
\begin{axis}[xlabel={$x$}, ylabel={$y$}, domain=0:4]
    \addplot {x^2 - 5*x + 6};
\end{axis}
```

Every axis inherits the `plot axes` style: left and bottom axes, outward ticks,
a light major grid, small labels/titles/legends, thick curves and 80 samples.
The four-curve cycle uses accent solid, black dashed, accent dash-dotted and
gray dotted lines. Use `\addplot` or `\addplot+[options]` to keep the cycle;
`\addplot[highlight]` or `\addplot[plot points]` selects an explicit style.

| Axis option | Plotting rectangle (width x height) |
| ----------- | ---------------------------------- |
| none | 9 x 5 cm |
| `small plot` | 6 x 4 cm |
| `wide plot` | 13 x 7 cm |
| `square plot` | 7 x 7 cm |

Sizes apply to the axis rectangle (`scale only axis`); labels and the border
add to the PDF dimensions. A square plot does not imply equal coordinate units.
Use a size option instead of scaling the finished PDF. Local options such as
`grid=none` or `axis lines=middle` override the defaults; ranges, ticks, labels
and legend placement are chosen per figure. Customize all plots in `myfigures.sty`:

```tex
\pgfplotsset{plot axes/.append style={width=10cm, height=6cm}}
\tikzset{node distance=8mm and 14mm}
```

### Subplots and CSV data

`subplot grid` selects 6 x 4 cm panels. The default grid has two columns,
one row, 15 mm gaps, and axis labels on the bottom row and left column:

```tex
\begin{groupplot}[subplot grid, domain=0:1, xlabel={$x$}, ylabel={$y$}]
    \nextgroupplot[title={(a) First}]
        \addplot {x^2};
    \nextgroupplot[title={(b) Second}]
        \addplot {sqrt(x)};
\end{groupplot}
```

Place `groupplot` inside one `tikzpicture`. Shared options go in `groupplot`;
local ones go in `\nextgroupplot[...]`. Panels fill left to right, then top to
bottom, restarting the curve cycle in each panel. Set
`group style={group size=2 by 2}` for four panels. If all panels share scales,
add `xticklabels at=edge bottom, yticklabels at=edge left` inside `group style`
to hide repeated tick labels. Change global spacing in `myfigures.sty` with
`\pgfplotsset{group/horizontal sep=18mm, group/vertical sep=18mm}`.

CSV files can use a header and numeric rows, like
[Linear.csv](Figures/Data/Linear.csv), with columns `x,measured,reference`.
Select named columns inside an `axis` or after `\nextgroupplot`:

```tex
\addplot table[col sep=comma, x=x, y=reference] {Figures/Data/Linear.csv};
\addplot[plot points] table[col sep=comma, x=x, y=measured]
    {Figures/Data/Linear.csv};
```

The first connects rows in file order; the second draws isolated points. Use
decimal points and one row per observation. For other formats, use
`col sep=semicolon`, or `header=false, x index=0, y index=1` for headerless data.
Paths are relative to the project root. CSV changes rebuild the affected figure
on the next `latexmk` run; no conversion script or extra build rule is needed.

PNG, JPEG and imported PDFs can also go in `Figures/`; use `git add -f` to track
an imported PDF. For companion Lua files, call `kpse.record_input_file` so the
build tracks them too.

## Example project

[Mechanics-Landau-Solution](https://github.com/pobol2/Mechanics-Landau-Solution)
is a real solution-manual project built on this template,
with subject-specific TikZ diagrams and numerical field tools for its figures. The template stays general:
specialized extensions like these belong in each manual's own files
(`mycommands.sty`, `myfigures.sty`, companion Lua files), not in
`solution-manual/`.
